Architecture and Objectives

Multi-engine stealth web scraping system for autonomous media extraction and AI dataset generation.

1.1 System Architecture

scrAPE is a multi-tier web extraction engine designed to crawl complex platforms, bypass WAF protections (Cloudflare, Incapsula, Datadome), and generate high-resolution image and video datasets for AI training models (Kohya_ss LoRA, Stable Diffusion).

[!] CORE OPERATIONAL GUARANTEE
The system executes via an 8-tier WAF fallback pipeline. Requests automatically escalate from lightweight direct HTTP up to headful stealth browser automation when challenge loops are detected. No manual intervention is required.

To defeat extension-spoofing attacks (e.g. PHP scripts or HTML 403 error pages named image.jpg), the downloader inspects the initial 16 bytes of the incoming byte buffer before writing to disk:

JPEG / JPG FF D8 FF 0 Verify SOI marker; parse SOF0/SOF2 segment for native dimensions.
PNG 89 50 4E 47 0D 0A 1A 0A 0 Validate PNG signature; read IHDR chunk for width, height, and bit depth.
WEBP 52 49 46 46 .... 57 45 42 50 (RIFF....WEBP) 0, 8 Verify RIFF container and VP8/VP8L/VP8X chunk dimensions.
GIF 47 49 46 38 37 61 / 47 49 46 38 39 61 (GIF87a / GIF89a) 0 Inspect Logical Screen Descriptor; reject single-frame tracking GIFs.
AVIF .... 66 74 79 70 61 76 69 66 (ftypavif) 4 Parse ISOBMFF box brand compatibility.
MP4 Video .... 66 74 79 70 (ftyp) 4 Verify video container header; inspect moov/trak atoms for track duration.

2.4 Command Recipes

Standardized execution recipes for production workflows, automated background tasks, and diagnostic audits:

RECIPE 1 // STANDARD SEED EXTRACTION WITH REJECTED MEDIA RETENTION 
python src/cli/main.py --keyword "example_subject" --seed seeds/example_subject.txt \
  --max-results 200 --workers 12 --dl-workers 16 \
  --page-limit 300 --crawl-depth 3 --download-media \
  --save-rejected "low_subject_relevance,preview_or_thumbnail"

System Exposition: Allocates 12 concurrent BFS discovery workers and 16 asynchronous stream downloaders. Retains discarded thumbnails and low-relevance media in output/{subject}/rejected/ rather than unlinking them, enabling operators to audit false-positive filter classifications and tune keyword score weights without re-running the crawl.

RECIPE 2 // CONTINUOUS WATCHDOG AGENT WITH STATE CACHE 
python src/cli/monitor_agent.py --keyword "example_subject" \
  --seed seeds/example_subject.txt --use-state-cache \
  --interval 120 --max-cycles 0

System Exposition: Boots the autonomous daemon mode (monitor_agent.py) executing recurring scrape loops every 120 seconds (--max-cycles 0 runs indefinitely). Binds to output/cache/state_cache.db with WAL mode; discovered URLs are evaluated against the SQLite bloom/hash index, ensuring only new/delta media assets are fetched. Dispatches run delta summaries to configured Telegram/Discord webhooks.

RECIPE 3 // QUICK VALIDATION RUN (NO DOWNLOADS) 
python src/cli/main.py --keyword "example_subject" \
  --seed seeds/example_subject.txt \
  --max-results 10 --page-limit 20 --crawl-depth 1

System Exposition: Dry-run diagnostic pass without --download-media. Traverses the seed manifest to depth 1, verifies DOM selector matches, audits target HTTP response codes, and writes domain_report.json with zero media bandwidth consumption. Used for CI/CD pre-flight checks and seed manifest validation.

RECIPE 4 // SEARCH-ONLY DISCOVERY (NO SEEDS) 
python src/cli/main.py --keyword "example_subject" \
  --max-results 50 --page-limit 100 --download-media \
  --enable-vlm --export-parquet

System Exposition: Cold-start bootstrap pass without an initial seed manifest. Queries configured search providers (Google Images, DuckDuckGo) for candidate galleries, expands outbound links up to 100 pages, applies self-healing VLM recovery for obfuscated markup, and compiles scraped records directly into high-compression Apache Parquet datasets.

RECIPE 5 // STEALTH CRAWL (POLITE SPEED)

  --seed seeds/example_subject.txt \
  --workers 2 --dl-workers 2 --page-limit 20 --crawl-depth 1 --download-media \
  --stealth-tier 7 --delay-min 2.5 --delay-max 6.0

System Exposition: Low-frequency stealth configuration targeting protected high-security hosts (Cloudflare Turnstile, DataDome). Constrains worker pools to 2 threads with randomized per-request jitter (2.5s to 6.0s), forces Tier 7 Camoufox browser spoofing with randomized mouse Bezier paths, and isolates cookie jars to prevent cross-origin tracking.

BFS Crawl Loop

Asynchronous link traversal queue and worker thread orchestration.

4.1 Execution Sequence & Queue State Machine

The crawling engine (src/core/engine.py) coordinates an asynchronous breadth-first-search traversal topology with per-domain rate limiting, bounded memory queues, and decoupled downloader workers:

  1. Seed Queue Initialization: Parse seed URLs and manifest header annotations (rate limits, CDN bindings, depth caps). Load domain policies into memory.
  2. Page Retrieval & WAF Escalation: Dispatch target URL to HTTP client, routing transparently through the 8-tier WAF fallback pipeline until a 200 OK or terminal error occurs.
  3. Self-Healing Content Parsing: Parse HTML DOM using BeautifulSoup/lxml. If classes are obfuscated, invoke SelfHealingDOMParser to extract candidate media items, anchors, and metadata.
  4. URL Normalization & Deduplication: Pass discovered URLs through normalize_url() using regex rules from data/url_normalisation_rules.json. Check visited Bloom filter and SQLite state cache.
  5. Scope & Relevance Validation: Check link depth, domain constraints, blacklists, and subject relevance scoring in src/core/filters.py.
  6. Decoupled Media Enqueue: High-scoring candidate media URLs pass to src/storage/downloader/manager.py thread pool without blocking crawler traversal.
  7. Recursive Queue Append: Discovered page links matching crawl rules append to the priority queue for depth N+1 processing.

Traversal State Machine & Worker Isolation

Lifecycle State Worker Component Operational Action & Invariants
DISCOVERED CrawlCoordinator Candidate link extracted from anchor; canonicalized via regex rules; discarded if present in VisitedSet.
QUEUED PriorityQueue Ranked via prioritization heuristic $P(u)$; bounded memory queue (default maxsize: 50,000) prevents OOM.
RATE_LIMITED PerDomainRateLimiter Token Bucket check per target hostname. If tokens depleted, worker sleeps or context-switches to alternative domain.
FETCHING HTTPClient / WAF Dispatches HTTP GET with TLS impersonation (Chrome 124); auto-escalates to Camoufox / DrissionPage on challenge.
PARSED SelfHealingDOMParser L1 cache lookup → JSON-LD microdata → VLM recovery. Extracts images, videos, and child hyperlinks.
DISPATCHED DownloadManager Assets transferred to streaming downloader worker pool; crawler continues traversal immediately without waiting for download I/O.

Priority(u) = [w_depth * (MaxDepth - depth(u))] + [w_kw * KeywordMatches(u)] + [w_yield * HistoricalYield(domain)] - Penalty(u)

Where:

URL Normalization

Six-stage canonicalization pipeline, regex transformation rules, and state cache deduplication.

4.5 Six-Stage Canonicalization Pipeline

Implemented in src/core/filters.py (normalize_url()), the canonicalization engine transforms arbitrary discovered web links into a deterministic canonical representation. This guarantees that URLs pointing to identical server resources are fetched exactly once:

Stage Canonicalization Action Example Input → Output
1. Scheme & Host Normalization Forces scheme and hostname to lowercase; strips standard default ports (:80 for HTTP, :443 for HTTPS); decodes punycode IDN domains. HTTP://Example.COM:80/path → http://example.com/path
2. Path Segment Resolution Collapses duplicate slashes (// → /); resolves dot segments (/a/b/../c → /a/c); enforces trailing slash policy. http://example.com//gallery/./pic.jpg → http://example.com/gallery/pic.jpg
3. Locale Directory Stripping Purges ISO-639-1 two-letter locale prefixes (e.g. /en/, /fr/, /ja/) from multilingual CMS platforms. http://example.com/fr/photo/123 → http://example.com/photo/123
4. Tracking Query Purge Strips marketing and analytics tracking parameters: utm_*, fbclid, gclid, ref, spm, _hsenc, yclid, session_id. http://site.com/view?id=42&utm_source=tw → http://site.com/view?id=42
5. Query Key Lexicographical Sort Sorts remaining operational query keys alphabetically, preventing duplicate fetches caused by varying key order in web frameworks. http://site.com/view?z=1&a=2 → http://site.com/view?a=2&z=1
6. Anchor Fragment Truncation Unconditionally removes client-side URL fragments (#section, #!hash), as HTTP servers do not receive or process fragments. http://example.com/page#top → http://example.com/page

Hierarchical Suffix Matching Mechanics

The blacklist validator (src/common/blacklist.py → is_blacklisted()) applies suffix boundary checking. When a parent domain is listed, all subdomains are automatically rejected without requiring wildcard syntax:

PYTHON // SUBDOMAIN MATCHING LOGIC 
def is_blacklisted(domain: str) -> bool:
    blacklist = load_blacklist()
    dom = domain.lower()
    for b_domain in blacklist:
        b_dom = b_domain.lower()
        # Matches exact domain OR any hierarchical child subdomain (.b_dom)
        if dom == b_dom or dom.endswith("." + b_dom):
            return True
    return False

    logger.warning(f"Task {task.task_id} already finalized by another worker. Discarding duplicate output.")
    redis_client.xack("scrape:crawl_stream", "scrape:cluster_workers", task.message_id)
    return

10.3.2 Cryptographic Hash Path Enforcement

Every object uploaded to or downloaded from cloud CAS is verified against its SHA-256 checksum both before transmission and after reception:

PYTHON // CAS KEY PATH VALIDATION & CHECKSUM VERIFICATION 
import re
from src.common.security import SecurityValidationError

HEX_SHA256_PATTERN = re.compile(r"^[0-9a-f]{64}$")

def build_cas_object_key(sha256_hash: str) -> str:
    """Builds a deterministic CAS S3 key. Strictly rejects non-hex characters and traversal payloads."""
    cleaned = sha256_hash.strip().lower()
    if not HEX_SHA256_PATTERN.match(cleaned):
        raise SecurityValidationError(f"Invalid CAS SHA-256 hash digest: {sha256_hash!r}")
    return f"cas/{cleaned[:2]}/{cleaned[2:4]}/{cleaned}"
